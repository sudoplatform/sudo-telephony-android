setEnforceSingletonKeyPair

fun setEnforceSingletonKeyPair(enforceSingletonKeyPair: Boolean): <Error class: unknown class>

Provide whether every phone number is provisioned with one shared key pair instead of a key pair of its own (optional input). Defaults to false.

When true, every number is registered with one shared key pair, which the app creates with createSingletonKeysIfAbsent before provisioning. The client never creates it itself: provisioning without it throws PhoneNumberException.SingletonKeyPairNotFoundException. The shared key pair is never removed when a number is deprovisioned or fails to provision; only reset removes it.

Messages are still sealed, but every number's messages are sealed to the same key, so all numbers can be read with that one key. Apps that don't need numbers kept cryptographically separate from one another can use this to keep key management and key export and import simple.

When false, each number gets its own key pair, which is removed from the device when the number is deprovisioned or when the service rejects its provisioning.
